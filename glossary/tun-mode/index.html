TUN虚拟网卡模式与系统代理的区别解析与开启方法

为什么开了系统代理，游戏客户端、Telegram桌面版或命令行依然无法连网？深度拆解TUN虚拟网卡与普通HTTP系统代理的工作层级与底层差异。

在电脑上使用 Clash Verge、v2rayN 或 Sing-box 时，你会发现有两种完全不同的代理运行机制：一种叫 “系统代理 (System Proxy)”，另一种叫 “TUN 虚拟网卡模式 (TUN Mode)”。

很多用户疑惑：既然系统代理已经能让 Chrome 和 Edge 打开 YouTube 了，为什么还要大费周章去安装虚拟网卡服务开启 TUN 模式？

一、工作层级与捕获范围的本质区别

[OSI 模型层级]
  应用层 (Layer 7)  ───>  【系统代理 System Proxy】 (仅接管主动遵从系统代理设置的软件，如浏览器)
       ▼
  网络层 (Layer 3)  ───>  【TUN 模式 TUN Mode】   (以虚拟网卡接管整台设备全部 IP 数据包)

1. 系统代理 (System Proxy)

  • 原理：客户端在操作系统网络设置中修改 127.0.0.1:7890 之类的环境变量。
  • 局限性：它是一个“君子协议”。只有主动去读取系统代理设置的应用程序（例如主流浏览器）才会听从调度。
  • 无法接管的软件：海外网络游戏客户端（如 Steam/EA/暴雪）、命令行终端工具（curl/git/pip）、以及部分采用自研网络栈的桌面通讯软件（如 Telegram 桌面端初次连接）。

2. TUN 模式 (TUN Mode)

  • 原理：客户端在操作系统内核中安装一块 虚拟网络适配器（Virtual TUN Device），并将系统全局的默认网络路由（Route Gateway）指向该虚拟网卡。
  • 优势：在三层网络（IP 层）实现对整台电脑全部进出数据包的 “无死角暴力接管”。任何软件无论是否支持代理设置，其产生的网络数据包都会被百分之百抓取并交由代理规则引擎处理。

二、对比汇总与适用场景

对比维度 普通系统代理 (System Proxy) TUN 虚拟网卡模式 (TUN Mode)
安装要求 零门槛，无需管理员权限驱动 需安装虚拟网卡服务（Service Mode）
接管范围 仅限浏览器等标准应用程序 全系统所有软件、游戏、终端进程
游戏加速能力 无法加速任何外服游戏 可接管外服网游并降低网络延迟
开销与功耗 极低 稍有提升（但现代电脑几乎无感）

三、开启 TUN 模式的通用步骤（以 Clash Verge 为例）

  1. 打开 Clash Verge，进入 设置 (Settings) 页面；
  2. 找到 服务模式 (Service Mode)，点击右侧的“安装”并授权 Windows/Mac 管理员权限；
  3. 安装成功后，找到 TUN 模式 开关并打开；
  4. 此时可关闭原来的“系统代理”开关，整台电脑的所有网络流量已完全受 TUN 模式托管！
